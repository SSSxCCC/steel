# 创建项目

本章会创建一个属于你自己的 Git 仓库，并从 Steel 的`empty-project`开始。请先按上一章克隆 Steel 仓库；以下示例假设 Steel 仓库和新项目是同级目录。

## 创建自己的仓库

1. 在 GitHub 上新建一个空仓库（不要勾选初始化 README、`.gitignore`或License）。
2. 克隆你的仓库：

```
git clone https://github.com/<你的用户名>/<你的仓库名>.git my-game
cd my-game
```

3. 将 Steel 仓库中的`examples/empty-project`内容复制到新仓库根目录。请复制隐藏文件，例如`.gitignore`。

Windows PowerShell：

```
Get-ChildItem ..\steel\examples\empty-project -Force | Copy-Item -Destination . -Recurse -Force
```

macOS/Linux：

```
cp -R ../steel/examples/empty-project/. .
```

如果 Steel 仓库不在新项目的同级目录，请将命令中的路径改为实际位置。

4. 修改`Cargo.toml`中的`package.name`和`[[bin]].name`为你的项目名。保留`[lib]`中的`name = "main"`，Android模板会加载`libmain.so`。删除`[dependencies]`下原有的`steel-engine`行（它指向Steel仓库的本地路径），然后用Cargo添加 crates.io 上最新稳定版 Steel：

```
cargo add steel-engine
```

这会将当前最新版本写入`Cargo.toml`。本教程针对 Steel 0.3，生成的依赖应为`steel-engine = "0.3.0"`。不要保留模板中的`path = "../.."`。

`Cargo.lock`会锁定本次解析出的具体版本，建议和应用代码一起提交。`cargo update -p steel-engine`可以更新锁文件中满足当前版本约束的Steel版本。Cargo遵循语义版本规则，0.x的小版本之间不兼容：发布Steel 0.4后，现有`"0.3.0"`约束不会自动跨到0.4。届时将依赖改为`steel-engine = "0.4"`（可执行`cargo add steel-engine@0.4`），再运行`cargo update -p steel-engine`。本教程会随Steel稳定版更新；重新按教程创建项目时，`cargo add steel-engine`会选择当时的最新版本。

## 运行项目和集成编辑器

在新项目根目录运行：

```
cargo run --features steel-engine/editor
```

不启用编辑器时运行`cargo run`。编辑器使用进程当前工作目录下的`assets`目录；创建该目录并将游戏场景和其他资源放在其中。

Windows PowerShell：

```
New-Item -ItemType Directory -Force assets | Out-Null
```

macOS/Linux：

```
mkdir -p assets
```

模板自带的入口位于`src/lib.rs`和`src/main.rs`。

修改Rust源码后，需要重新构建并启动应用。“Project -> Compile”菜单不会调用Cargo编译源码。教程接球游戏的完整实现仍可参考Steel仓库的`examples/ball`。

## 提交到自己的远程仓库

```
git add .
git commit -m "Create Steel game project"
git push -u origin main
```

如果GitHub新仓库的默认分支不是`main`，请将命令中的分支名替换为实际名称。
